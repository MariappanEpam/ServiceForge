## Key findings (gaps / risks)

1) Repo convention mismatch (SQLite vs in-memory)
- The repo overview states “in-memory mock data”, while Feature 7 assumes SQLite as source of truth.
- This is acceptable only if Feature 5 introduced SQLite and project decisions/rules confirm it.

2) ApiError + exception mapping not fully specified
- Architecture references `ApiError` semantics but does not explicitly require a single global exception handler mapping domain exceptions to `ApiError`.

3) Delete guard coupling risk
- The optional delete guard depends on reservation schema and an “ACTIVE” status definition.
- Without explicit schema/status definitions, implementing the guard risks brittle coupling.

4) Search semantics ambiguity
- Case sensitivity and trimming behavior for `q` are not specified.
- SQLite collation differences can cause inconsistent UX.

5) Seed compatibility not explicit
- If existing reservation demos/tests depend on specific SKUs, baseline seed must include them.

## Adjustments applied
- Created reviewed architecture doc: pipeline/architecture-design/feature-7-architecture.md
  - Added explicit clarifications for search semantics, inactive SKU handling, and conditional delete guard.
  - Added explicit requirement for consistent `ApiError` mapping.
  - Added seed compatibility note.
- Added pointer note to the original handoff architecture file to direct readers to the reviewed doc.
