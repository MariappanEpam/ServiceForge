# Repository agent instructions

Purpose
- Provide a concise, machine-readable instruction set for coding agents working in this repository.

Scope
- Applies to all backend, frontend, and test code and to any agent that creates, modifies, or organizes source files in this workspace.

Primary rule
- All backend, frontend, and test code implementation MUST be placed under the single top-level folder: main
- Canonical path: ServiceForge-Start/main
- If the `main` folder does not exist, agents should create it before adding code.

File layout expectations
- Backend Java code: main/backend/...
- Frontend Angular code: main/frontend/...
- Tests: main/tests/ or colocated under main/backend/...-test and main/frontend/...-test
- Tools, scripts, CI helpers: main/tools/

When to apply
- On new feature implementation, refactors, or when adding tests.
- When scaffolding projects (do not scaffold outside the `main` folder).

Migration guidance
- Agents should NOT automatically move existing files without explicit user consent.
- When a change requires moving files, create a PR that documents the move and leaves redirects (README notes) explaining the new layout.

Enforcement and checks
- Prefer creating a short README at the repository root and at main/ describing the layout.
- Include file patterns to check in PR descriptions, e.g. "All new source files under main/".

Examples (prompts agents can follow)
- "Create a new backend controller at main/backend/src/..." 
- "Add frontend component files under main/frontend/src/app/..."
- "Add unit tests under main/tests/unit/..."

Clarifying questions for the maintainer
- Should this rule apply to generated build artifacts and target directories, or only to source files?
- Do you want existing top-level backend/frontend folders (currently `backend/` and `frontend/`) moved into `main/` now, or only for new work going forward?

Notes
- This file is intentionally short and prescriptive — update it if the team decides to adopt a different top-level layout or to split repositories.
